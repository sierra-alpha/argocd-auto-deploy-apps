# Kubernetes deployment reliability audit — first safe slice

Control job: https://github.com/sierra-alpha/ai-whisperer/pull/66

## Verified from repository manifests

- **Audiobookshelf:** The existing exec liveness probe checks podcast-volume writability, not the HTTP listener. Add a separate HTTP readiness probe on port 80 to keep the Service from routing to an unavailable web listener. Keep the storage liveness check and hard pin to `prosomniac`: the SQLite config is node-local and must not silently fail over.
- **Coqui TTS:** The deployment exposes port 5002 but had no probe. Add TCP readiness only. Do **not** add an aggressive liveness/startup restart policy until cold model-download/startup durations have been measured; an incorrect liveness threshold could cause restart loops.
- **Podsort:** `audiobookshelf/kustomization.yaml` previously disabled the generated `podsort-code` ConfigMap name hash. The Python source is mounted as a directory, but the running Uvicorn process does not automatically reload code on ConfigMap updates. Enable the suffix hash so Kustomize rewrites the Deployment's ConfigMap reference when `rss_sorter.py` changes and Kubernetes performs a controlled rollout. No image, secret, or application code changes are required.
- **Homepage:** `homepage/kustomization.yaml` uses a ConfigMap generator with `disableNameSuffixHash: false`. Kustomize rewrites the Deployment reference when generated ConfigMap content changes, triggering a pod-template rollout even though individual files are mounted with `subPath`. No duplicate restart annotation is needed.
- **Secret rotation:** Podsort consumes its OnePassword-managed Audiobookshelf API token through an environment variable (`secretKeyRef`). Kubernetes does not update that value inside a running container when the Secret changes; the Deployment has no secret-change rollout trigger. The rclone DaemonSet similarly mounts a OnePassword-managed config file, but a live config-volume update does not guarantee the running rclone process reloads it. Both need a separate, reviewed rotation/restart design; do not infer that Argo CD's Git self-heal handles out-of-band Secret changes. The hourly `ttser` CronJob starts fresh pods, so its environment-sourced secret is refreshed at each new Job. Do not introduce an unverified cluster-wide reloader or publish secret contents.
- **Resources:** Audiobookshelf and Coqui TTS lack explicit requests/limits. Defer sizing until actual memory and CPU usage, model-load peaks and node headroom are measured; guessing memory limits could kill a healthy service.
- **Immich:** `immich/immich.yaml` currently contains commented-out workload examples, not an active Deployment; do not apply probes to dead configuration.

## Validation and rollout

This PR changes readiness gates, Podsort code ConfigMap rollout wiring, and documentation; it does not alter liveness, scheduling, secrets, or live workloads. Before merge, render manifests and validate against the Kubernetes API schema in a safe environment. Verify that changing `audiobookshelf/rss_sorter.py` changes the generated `podsort-code` ConfigMap name and Deployment pod template, and that an unchanged source does not create a new rollout. Then verify Service endpoints and pod readiness through a staged rollout. Check cold-start behavior and whether Audiobookshelf's root endpoint returns a 2xx/3xx response. The repository audit cannot establish live cluster behavior. No automatic merge or deployment is authorized.
